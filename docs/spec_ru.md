# Техническое задание: Мобильное приложение «Pulse»
*(с поддержкой русского и английского языков)*

> Источник истины для продукта. Любые расхождения между этим документом и
> кодом считаются багом — либо в коде, либо здесь.

## 1. Общее описание проекта

**Pulse** — мобильное приложение для парного и множественного взаимодействия
без текста, лайков, лент и публичности. Взаимодействие между доверенными
пользователями строится исключительно на сенсорных, тактильных, аудиальных и
световых сигналах. Приложение позволяет хранить несколько связей (подруг,
друзей), входить в активную сессию с одним человеком или внезапно вмешиваться в
чужую активную сессию коротким звуком/вибрацией (механика «Sneak In»).

Ключевая философия: **полная приватность, никаких аккаунтов, нулевой сбор
данных, работа без интернета**. Связи устойчивы к разрывам сети и расстоянию —
они разрываются только явным действием пользователя.

## 2. Целевая аудитория

- Пары, близкие друзья, подростки (13+).
- Пользователи, уставшие от текстовых мессенджеров и социальных сетей.
- Устройства: бюджетные и средние смартфоны (ОЗУ от 2 ГБ, процессоры
  Snapdragon 4xx, MediaTek Helio G2x/A2x, Apple A10 и новее).
- **Языковая доступность:** русский и английский на старте, с возможностью
  добавления других языков в будущем.

## 3. Платформы и поддерживаемые устройства

- **iOS 15+**, **Android 10+**.
- Экраны от 4.7" (iPhone SE) до планшетов и складных устройств (Fold/Flip).
- Минимальные аппаратные требования: 2 ГБ ОЗУ, поддержка BLE 4.2+.

## 4. Фундаментальные принципы

- **Никакого текста.** Только сенсорика: касания, вибрация, звук, свет, движение.
- **Никаких аккаунтов.** Все связи хранятся локально на устройстве.
- **Нулевой сбор данных.** Никакая аналитика, телеметрия или логи не
  собираются (кроме явно разрешённых crash reports).
- **Равноправие.** Оба участника любой связи имеют одинаковые интерфейсы и
  возможности.

## 5. Сетевое взаимодействие и оффлайн-режим

Приложение использует три транспортных канала с автоматическим выбором лучшего:

1. **Прямое соединение**
   - **BLE** (Bluetooth Low Energy) — фоновое поддержание связи, передача
     коротких сигналов и «Sneak In».
   - **Wi-Fi Direct** (Android) / **Multipeer Connectivity** (iOS) — для
     активных сессий с высоким потоком данных (звук, непрерывная тактильная
     отдача).
2. **Локальная сеть без интернета**
   - mDNS/Bonjour для обнаружения партнёра в одной Wi-Fi сети, если прямой
     канал недоступен.
3. **Интернет-реле**
   - **WebRTC** с сквозным шифрованием (DTLS-SRTP).
   - Сигнальный сервер (STUN/TURN) используется исключительно для установки
     соединения и не видит содержимого трафика.
   - Все данные после установки канала передаются P2P и шифруются симметричным
     ключом пары.

**Приоритет каналов:** прямой (BLE / Wi-Fi Direct) → локальная сеть →
интернет-реле.

**Отказоустойчивость:** связь никогда не рвётся автоматически. При временной
потере всех каналов приложение переходит в режим «поиск» с экспоненциальной
задержкой, сохраняя ключи. При восстановлении любого канала сессия (или
возможность Sneak In) восстанавливается бесшовно.

## 6. Приватность и безопасность

- **Первое сопряжение:** обмен публичными ключами по Curve25519 (ECDH) для
  генерации общего симметричного ключа. Обмен защищён коротким одноразовым
  кодом из 6 цифр или QR-кодом.
- **Шифрование канала:** AES-256-GCM для всех данных.
- **Хранение ключей:** исключительно локально, в системном защищённом
  хранилище (iOS Keychain, Android EncryptedSharedPreferences). Каждая связь —
  отдельная запись с уникальным ключом.
- **Идентификаторы для переподключения:** случайные токены, генерируемые при
  создании пары, не привязанные к личности или устройству. Сигнальный сервер
  видит только соединение двух токенов без какой-либо идентификации.
- **Разрыв связи:** при явном удалении пары ключ уничтожается локально,
  партнёру отправляется зашифрованный сигнал «удалить связь». Восстановить
  историю невозможно.
- **Доступы:** приложение не запрашивает контакты, геолокацию (кроме фонового
  разрешения на BLE, обязательного для обнаружения, но координаты не
  считываются), галерею (только при явном сохранении артефакта пользователем).
- **Аудит безопасности:** исходный код должен быть подготовлен к независимому
  аудиту.

## 7. Модель множественных связей и механика «Sneak In»

### Локальное хранилище связей

Каждая доверенная связь хранится локально и содержит:

- UUID связи,
- Локальный псевдоним (эмодзи/цвет/имя, задаётся пользователем, не передаётся),
- Симметричный ключ AES-256,
- Публичный ключ партнёра (для возможного восстановления канала),
- Случайные токены для переподключения (BLE-адрес, сигнальный токен),
- Статус: **активна** (полный дуплекс), **пауза** (только теневой канал для
  Sneak In), **архив** (без автоматического переподключения),
- Разрешения: битовая маска — разрешить полные сессии, разрешить Sneak In,
  требовать подтверждение при первом вмешательстве.

### Переключение активной связи

- Одновременно активна только **одна полная сессия**.
- Переключение выполняется через экран «Мои люди»: текущая сессия ставится на
  паузу (партнёру уходит статус «отошла»), активируется новая.
- Возврат к предыдущей связи происходит мгновенно без повторной привязки.

### Механика «Sneak In» (внезапное вмешательство)

- Если связь находится в статусе «пауза» и у неё разрешён Sneak In,
  пользователь может отправить **один короткий сигнал** (звук + вибрация)
  своему партнёру, даже когда у того активна сессия с кем-то другим.
- Сигнал **не прерывает** активную сессию: звук миксуется с текущим аудио,
  вибрация добавляется кратковременно (1–2 секунды).
- Получатель видит на 2 секунды иконку отправителя и слышит выбранный звук.
- Получатель может мгновенно ответить встречным сигналом, не выходя из
  активной сессии.
- **Ограничения в бесплатной версии:** 1 Sneak In в день на контакт. В
  платной — без ограничений (в разумных пределах, настраиваемых).
- Технически: для неактивных связей поддерживается теневой BLE-канал
  (характеристика `sneak_signal`) или push-токен через интернет-реле.

### Управление разрешениями

Для каждой связи можно индивидуально задать:

- Разрешить полные сессии,
- Разрешить Sneak In,
- Требовать подтверждение при первом вмешательстве,
- Заблокировать (архивировать) — ни сигналов, ни сессий.

## 8. Встроенные микро-режимы (механики)

Режимы запускаются только в активной сессии. Интерфейс каждого режима —
полноэкранный, без текста. Выбор режима — через горизонтальную карусель на
главном экране.

Всего режимов в приложении — 15+ (с возможностью добавления). Для триала и
подписки используется разделение:

### Стартовый набор (7 режимов, доступных в бесплатном триале)

1. **Тук-Тук** — стук пальцем → вибрация и световое кольцо на экране партнёра.
   Поддержка ритмических последовательностей.
2. **Половина сердца** — каждый касается своей половинки, при удержании обоими
   пальцами половинки соединяются в общее пульсирующее сердце.
3. **Свечка** — зажигание виртуальной свечи касанием у одного → загорается у
   другого. Дуновение в микрофон → гаснет у обоих.
4. **Шёпот** — шёпот в микрофон → звуковые волны на экране партнёра и тихая
   вибрация в такт, без передачи голоса.
5. **Колокольчик** — встряхивание телефона → мелодичный звон, громкость и тон
   зависят от силы встряски.
6. **Лучик** — ведение пальцем → тонкая полоска света на экране партнёра.
7. **Созвездие** — рисование звёзд на чёрном небе, после поднятия пальцев
   звёзды соединяются в общее созвездие.

### Полный набор (по подписке)

Дополнительно открываются: Мурашки, Ниточка, Гром, Фейерверк, Баланс,
Песочница, Дыхание, Синхро и все будущие режимы.

Все режимы проектируются с возможностью адаптивной деградации эффектов на
слабых устройствах (отключение сложных частиц, снижение FPS до 30).

## 9. Монетизация и подписка

### Модель

- **Бесплатный триал (7 дней):** пользователь получает доступ к **7 стартовым
  режимам** (перечислены выше), может создать до 3 сохранённых связей и
  отправлять Sneak In не чаще 1 раза в день на контакт. Полный набор режимов
  и безлимитный Sneak In недоступны даже в триале.
- **По окончании триала без подписки:** остаются только 2 базовых режима
  (Тук-Тук и Половина сердца), 1 Sneak In в день, до 2 сохранённых связей.
- **Подписка (150 руб/мес):** полный доступ ко всем текущим и будущим режимам,
  безлимитный Sneak In, до 10 сохранённых связей, приоритетная поддержка
  новых функций при обновлениях.
- **Оплата:** через встроенные механизмы магазинов (Apple In-App Purchase,
  Google Play Billing). Подписка привязывается к учётной записи магазина;
  статус проверяется локально по квитанции (без обязательной серверной
  валидации на старте). Детальная проработка платёжного флоу будет выполнена
  на финальном этапе.
- **Экран подписки:** минималистичный, всплывает при попытке открыть
  недоступный режим или превысить лимиты. Оформлен в общей тёмной эстетике,
  без агрессивного маркетинга.
- **Восстановление покупок:** кнопка Restore Purchases в интерфейсе.

## 10. Пользовательский интерфейс и UX

### Основные экраны

- **Сопряжение:** «Создать пару» (генерирует код/QR), «Присоединиться» (ввод
  кода). Анимация установления защищённого канала. Можно сразу задать
  локальный псевдоним.
- **Главный хаб:** карусель иконок режимов, свайп для выбора, длинное нажатие
  для запуска. Индикатор типа подключения (зелёный – прямой, синий –
  локальная сеть, жёлтый – интернет-реле).
- **Экран активного режима:** полноэкранный, только жесты согласно механике,
  полупрозрачная кнопка «Выйти в хаб».
- **Мои люди:** список сохранённых связей с аватарками, статусами. Длинное
  нажатие → меню: «Сделать активной», «Подкрасться», «Настройки разрешений».
- **Подкрасться:** колесо из 8-12 звуков, свайп вверх — отправить.
- **Уведомление о вмешательстве:** небольшое облачко с эмодзи отправителя на
  2 секунды, звук, вибрация. Свайп вниз — быстрый ответ.
- **Отсутствие истории:** ни лент, ни записей, всё в реальном времени.

### Адаптивность и совместимость

- Вёрстка полностью на Auto Layout (iOS) и ConstraintLayout (Android).
  Никаких фиксированных пиксельных размеров.
- Основная ориентация — портретная. На планшетах (ширина >600dp) интерфейс
  центрируется, возможно будущее двухпанельное представление.
- Поддержка safe area, челок, вырезов, навигационных жестов.
- Ресурсы под разные плотности (mdpi–xxxhdpi, @2x/@3x).
- Тёмная тема по умолчанию, мягкие анимации.

### Локализация

- **Языки интерфейса:** русский и английский в обязательном порядке (MVP).
  Вся текстовая часть интерфейса (кнопки, диалоги, сообщения об ошибках,
  подписка, разрешения) должна быть вынесена в строковые ресурсы
  (`Localizable.strings` / `strings.xml`) с поддержкой плюрализации и
  форматирования.
- **Переключение языка:** автоматическое на основе системной локали.
  Предусмотреть возможность ручного выбора языка в настройках (второстепенная
  задача, можно добавить позже).
- **Архитектура для будущих языков:** все строки изолированы в файлах
  локализации. Добавление нового языка должно требовать только перевода этих
  файлов без изменения кода.
- **Названия режимов** (отображаемые в карусели, если текстовые подписи
  используются) также локализуются, но по умолчанию режимы идентифицируются
  иконками, что снижает зависимость от языка.
- Звуковые сигналы вмешательства (пук, икота и т.п.) культуронезависимы и не
  требуют перевода.

## 11. Фоновый режим и уведомления

- **BLE Background Execution** (iOS/Android) для поддержания жизни всех
  теневых каналов и приёма Sneak In.
- При свёрнутом приложении активная сессия может продолжать воспроизводить
  звук и вибрацию (с ограничениями ОС). Эффекты на экране приостанавливаются
  до возвращения в приложение.
- **Push-уведомления без содержимого** (только для интернет-реле), чтобы
  разбудить приложение и инициировать WebRTC-соединение.
- **Локальные тактильные уведомления:** с разрешения пользователя, для
  сигналов Sneak In, когда приложение в фоне.

## 12. Производительность и оптимизация

- **Размер приложения:** ≤ 50 МБ.
- **Потребление ОЗУ:** в фоне с BLE — не более 60 МБ; в активной сессии — до
  120 МБ.
- **Графика:** аппаратно-ускоренный Canvas / базовые API
  (SpriteKit/OpenGL ES 2.0), без тяжёлых движков. Адаптивная деградация
  сложных анимаций (отключение частиц) на слабых GPU.
- **Целевой FPS:** 60 кадров/с на бюджетных устройствах; минимальный порог —
  30 FPS в режимах с комплексными эффектами.
- **Аудио:** моно, 22 кГц, кодек Opus 16 кбит/с для минимизации задержки и
  нагрузки на ЦП.
- **Вибрация:** только стандартные системные API во избежание несовместимости
  со слабыми вибромоторами.

## 13. Этапы разработки (MVP)

1. **Базовое P2P-соединение и менеджер связей:** реализация BLE, Wi-Fi
   Direct/Multipeer, WebRTC с E2E-шифрованием. Генерация и локальное хранение
   ключей, переключение активной связи.
2. **Механика Sneak In:** теневые BLE-каналы (характеристика `sneak_signal`),
   push-токены, отправка и приём коротких сигналов, UI колеса звуков.
3. **7 стартовых режимов:** с учётом адаптивной деградации и минимальной
   задержки.
4. **Хаб, навигация, экран «Мои люди»:** управление разрешениями, статусы,
   контекстное меню.
5. **Фоновый режим:** переподключение без разрыва, восстановление сессий,
   фоновые уведомления.
6. **Система подписки и триала:** локальная проверка флагов, экран подписки,
   заглушка для будущей интеграции с магазинами.
7. **Локализация на русский и английский:** подготовка строковых ресурсов,
   проверка вёрстки с разной длиной текстов.
8. **Оптимизация под слабые устройства:** тестирование на бюджетных моделях,
   профилирование потребления ресурсов.
9. **Расширение библиотеки режимов:** добавление по 2–3 новых режима в каждом
   последующем спринте.

## 14. Дополнительные требования и ограничения

- Приложение не содержит рекламы.
- Полное отсутствие сбора телеметрии (кроме опциональных crash reports с
  явного согласия).
- Исходный код готов к аудиту безопасности.
- Поддержка восстановления покупок через стандартные API магазинов.
- Локализация должна быть легко расширяемой — архитектура строковых ресурсов
  с первого дня разработки.
